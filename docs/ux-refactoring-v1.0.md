# 박자표 피자 화덕 | 첫 30초 UX 리팩토링 설계서

**v1.0 · 2026-11-19 · 구현 전 설계**
기준: [사용자 구상안](https://docs.google.com/document/d/1tzKlJtjCfPGZ9BZXOnkqJnARC-cLzJvdqFYPK1GhiCI/edit) · [기준 커밋 82bda2c](https://github.com/kimyounggaur/time_signature_pizza_oven_game/tree/82bda2c81017b5022c85c686faff12545d6430d0) · [기존 구현·검증 기록](https://github.com/kimyounggaur/time_signature_pizza_oven_game/blob/82bda2c81017b5022c85c686faff12545d6430d0/docs/implementation.md)

**결정:** 처음에는 주문을 고르거나 음표 이름을 맞히지 않는다. 같은 4분음표를 두 번 올려 2/4 한 마디를 만든다. 이어서 조각 크기는 그대로 두고 한 개만 더 올린다. 학생이 바꾼 것은 음표가 아니라 **한 마디에 들어가는 박 수**다.

1차 변경은 **진도와 분리된 맛보기 1개 + 0단 첫 주문 안내**다. 기존 게임을 새 엔진으로 다시 만들지 않는다. 아래의 테스트·수업 관찰·구현 절차는 향후 작업 지시이며, 이 설계서를 작성하면서 앱을 수정·배포하거나 학습자 실험을 수행하지 않았다.

## 1. 무엇을 바꾸고 무엇을 보호하는가

| 구분 | 기준판에서 보이는 것 | 바꿀 것 / 보호할 것 |
|---|---|---|
| 첫 방문 | 타이틀 → 영업일 지도 → 0단 ‘조각 익히기’ → 소리 확인 → 첫 주문 | 기본 주소는 바로 두 박짜리 피자판. 지도·룰북·설정은 보조 경로. 강제 소리 확인 없음 |
| 정규 첫 주문 | `d0-01`은 `slot:"2", tray:"4"`. 2분음표 **자리**를 4분음표 두 개로 채운다. 여섯 버튼 중 하나만 유효 | 맛보기와 별개. 실제 주문에는 박자표를 붙이지 않고 ‘이 자리 길이를 작은 조각 두 개로 맞춰요’라고 연결. 데이터·정답·도장은 그대로 |
| 한 판의 의미 | 판 한 바퀴는 온음표 길이. 기존 눈금 한 칸은 8분음표 | 4분음표 한 개의 넓이·각도를 고정한다. 맛보기에서는 ‘박 자리’라 부르고, 기존 8분음표 눈금의 ‘칸’과 구별 |
| 재방문 | 타이틀의 ‘이어서 영업’이 유효한 체크포인트를 연다 | 이어하기 우선권 유지. 맛보기를 다시 해도 주문·최고 기록·메뉴판 불변 |
| 기존 자산 | 5영업일(d0~d4), 39주문, 발견 S1~S4, 6종 조각, 메뉴판 69칸·엇박 선반, 자유 화덕, 삽화 룰북 | 주문 추가·순서 변경·자동 해금 없음. 정규 채점·다시 내기·저장 복원·단일 HTML 오프라인 실행 보존 |

**학습의 경계:** 식빵 공방은 ‘한 박 안에서 몇 등분하는가’, 피자 화덕은 ‘한 마디를 몇 박으로 채우며 어떻게 묶는가’다. 이번 첫 과제는 박자 맞춰 탭하는 리듬 게임이 아니다. 빠른 탭·느린 탭·무음 탭 모두 똑같은 조각 하나다. 시간 제한, 실패음, 타이밍 점수, 자동 오답 처리를 만들지 않는다.

## 2. 학생이 보게 될 첫 30초

아래 시간은 **화면 구성의 목표**이지 타이머나 강제 전환 시각이 아니다. 30초가 지나도 계속 조작한다.

| 목표 시간 | 화면·문구 | 학생 행동 → 즉시 보이는 결과 |
|---|---|---|
| 0~5초 | 제목 ‘두 박 피자를 만들어요’ · 2/4 · ‘한 자리에 한 박. 빈자리를 채워요.’ · 번호 ① ② · 큰 버튼 **[한 박 조각 올리기]** (작게 ‘♩ 4분음표’) | 첫 탭 전에는 소리 허가·주문 카드·6종 쟁반·캐릭터 설명창이 없다. [하나 빼기], [한 마디 구워 듣기]는 아직 비활성 |
| 5~15초 | ①을 채우면 ‘한 박 놓았어요. 1박 남았어요.’ | 같은 버튼을 다시 눌러 ②를 채운다. ‘2박, 꽉 찼어요.’ 원래 버튼은 더 넣지 못하게 하고 **[한 마디 구워 듣기]**를 활성화. 빼면 바로 이전 상태 |
| 15~22초 | ‘첫 박 · 둘째 박’ · ①에는 굵은 테두리+‘첫 박’, ②에는 가는 테두리 | 굽기 한 번 → 한 마디만 ①·②가 차례로 강조된다. 음량 0이어도 같은 순서. 끝나면 2/4 완성 요약을 남기고 3/4판으로. 재생 중 [바로 비교] 가능 |
| 22~30초 | 3/4판: **이미 놓은 두 조각 + 새 빈 자리 ③**. ‘같은 조각을 하나 더 올려 볼까요?’ | [한 박 조각 올리기] **한 번만** → ‘같은 4분음표로 2박에서 3박이 됐어요.’ 2/4와 3/4의 기준 조각 표시를 나란히 유지. [세 박 들어 보기]는 선택 |
| 이후 | ‘아래 숫자 4: 4분음표가 기준이에요. 위 숫자 2와 3: 그 기준이 한 마디에 두 개, 세 개 들어가요.’ | 기본 다음 행동 **[첫 주문으로]**. 작은 [다시 만들기]·[더 발견하기]는 선택. 어느 쪽도 첫 완료 조건이 아님 |

**화면 스케치** (아래 타일은 원형 피자판 아래의 직선 읽기 보조줄이다):

~~~text
박자표 피자 화덕                      지도  룰북  설정
두 박 피자를 만들어요
         2                    2/4: [① 첫 박][② 둘째 박]
         4     (피자판)       박 자리 외 나머지 원판은 ‘안 쓰는 판’
               [한 박 조각 올리기 ♩]
         [하나 빼기]      [한 마디 구워 듣기]
~~~

3/4에서는 두 기존 조각을 재배치해 작게 만들지 않는다. ‘왼쪽부터 올리기’는 보조줄의 왼쪽→오른쪽 순서이고, 원판은 기존대로 12시→시계 방향이다. 2/4의 사용 범위는 180°, 3/4는 270°, 4분음표는 둘 다 90°다. **‘꽉 찼다’는 도우가 다 찼다는 뜻이지, 나무 원판 전체가 덮였다는 뜻이 아니다.** 첫 화면의 두 자리 사이를 빈 시간이나 쉼표처럼 표현하지 않는다.

## 3. 진입, 이탈, 재방문 계약

맛보기를 `d0-00`이나 자유 화덕 주문으로 구현하지 않는다. 제안 경로명은 내부 화면 상태 `taster`이며 새 서버 URL은 필요 없다. 첫 진입을 한 번 판정한 뒤, 모든 `render()`마다 강제로 맛보기로 보내지 않는다.

| 진입 조건 (위에서 먼저 일치하는 항목) | 목적지·동작 |
|---|---|
| 기존 `#test`, 초기 `#d0`~`#d4` | 현행 자가검사/직행 동작 그대로. 맛보기 자동 시작·완료 표시 없음. 같은 페이지 안에서 해시가 변할 때는 기존 해시 처리의 동작 범위를 별도 회귀검사 |
| 유효한 `save.active` 있음 | 기존 타이틀. **[이어서 영업]이 첫 선택**이고 그 버튼이 `Game.resume()`를 부른다. 새 `startDay`로 덮어쓰지 않는다. 체크포인트의 주문부터 시작하는 현행 복원 수준 유지(조립 중 배치까지 복원된다고 약속하지 않음) |
| 완료/건너뜀 표시 또는 이전 학습 흔적 있음 | 기존 타이틀. [30초 맛보기 다시 하기]를 보조로 추가. 흔적 판정: 유효한 active, days의 runs/passed/best, stats, 메뉴·선반·scenes, 기존 조작 팁 또는 소리 확인 기록. 단지 기본 설정이 있거나 저장 키가 존재한다는 사실만으로 판단하지 않음 |
| 위에 해당하지 않는 기본 주소 | 바로 `taster.two`, 빈자리 두 개. 저장 차단·손상 복구로 진도 없는 경우도 동일. 기존 복구·백업 안내는 숨기지 않음 |
| 타이틀에서 맛보기를 수동 실행 | 주문 체크포인트를 읽기만 한다. 완료/종료 후 active가 있으면 기본 CTA **[이어서 영업]**, 없으면 [첫 주문으로]. 정규 주문으로 넘어갈 때만 진도 생성 |
| 맛보기 중 지도/나가기 | 화면 전환 직전 맛보기 재생 취소. [지도]는 지도, [처음으로]는 타이틀. 명시적으로 종료한 경우에만 본 표시. 실수로 새로고침한 미완료 맛보기는 처음부터 재시작 가능 |
| 룰북·설정 열기 | 이동이 아니라 일시 정지. 재생·예약만 취소하고 채운 조각과 비교 단계 보존. 닫으면 호출 버튼으로 초점 복귀. 설정→소리 확인은 기존 동작 유지 |

**저장 결정:** 새 저장 키나 저장 버전은 만들지 않는다. `settings.tasterSeenV1`(boolean, 기본 false)을 `freshSave`와 `normalizeSave`의 허용 목록 양쪽에 명시한다. 런타임에 필드만 추가하면 다음 복원 때 버려진다. 오직 비교 완성·명시적 건너뛰기/나가기에서 중복 없이 기록한다. 배치·오디오·중간 시간은 저장하지 않는다. `settings.tips=[]`로 ‘조작 안내 다시 보기’를 해도 진입 기록은 지워지지 않는다. 기존 파일에 필드가 없으면 false이고, 위 재방문 판정에서 실제 진도가 우선한다. 저장 불가 시 같은 탭에서만 표시를 기억하고 다음 방문을 보장하지 않는다.

**첫 주문 연결:** `start(id, {fromTaster:false})`처럼 호출 이유를 분리한다. 맛보기 [첫 주문으로]에서만 `d0`의 자동 `soundCheck()`를 건너뛴다. 음소거를 강제하거나 `soundChecked=true`를 만들지 않는다. 기존 지도/딥링크의 확인 동작과 설정 안의 [소리 확인하기]는 보존한다. 기존 active가 있으면 `resume()`을 선택한다. 첫 주문 진입 전 안내: ‘방금은 한 마디를 채웠어요. 이번에는 2분음표 한 개의 **길이만큼** 채워요.’ `d0-01`일 때만 `① 4분음표 올리기 → ② 같은 조각 한 번 더 → 굽기`를 상태에 맞춰 하나씩 보여 준다. 다른 주문·다시 내기·최종 주문의 기존 도움말과 채점 우선순위를 바꾸지 않는다.

## 4. 상태 모델과 조작 명세

제안 파일 `src/taster.js`는 순수 모델이다. 입력은 이벤트, 출력은 다음 상태와 효과(예: 한 마디 재생 요청). 저장·DOM·시계·오디오를 직접 만지지 않는다. `Game.state.screen`은 분기용, 맛보기의 fill·재생 상태는 정규 `Game.state.fill/phase/queue`와 분리한다.

| 상태 | 유효 입력과 전이 | 불변 조건 |
|---|---|---|
| `two(n=0..2)` | ADD → 다음 자리에 N(4). UNDO → 마지막 하나 제거. n=2의 BAKE → `playTwo` | n=0에서 UNDO, n=2에서 ADD, n<2에서 BAKE는 무반응. 대기·재시도 시간 제한 없음 |
| `playTwo` | 정상 END 또는 [바로 비교] → `three(n=2)`. STOP·대화상자·탭 숨김 → `two(2)` | [멈추기]는 완료가 아니다. 음향 불가만으로 멈추거나 보상을 주지 않음 |
| `three(n=0..3)` | 진입 때만 2개 복사. ADD·UNDO는 한 개씩. n=3 도달 → `compare` | 두 조각을 잠가 억지로 정답 만들지 않음. 하나 빼면 다시 놓을 수 있음. 두 판은 배열 참조를 공유하지 않음 |
| `compare` | [세 박 들어 보기]/[다시 듣기] → 같은 비교 화면에 재생 후 정지. [하나 빼기] → `three(2)`. 다음/다시/확장 선택 | 완료 효과는 첫 진입에 한 번. 스코어·항목 수·도장 변화 없음. 비교 카드는 2/4=둘, 3/4=셋을 동시에 설명 |
| `moreLength`, `moreGroups` (2차 선택) | 2/4 길이 비교 또는 S3 미리보기. 돌아가기 → `compare`; 정규 진행과 독립 | 자료·표시만 재사용. 미리보기로 S3를 ‘발견 완료’ 기록하거나 d3를 해금하지 않음 |
| 모든 화면의 EXIT/OPEN_DIALOG/VISIBILITY_HIDDEN | 손가락/키 처리 중지, 대기 중 해제·예약·애니메이션 취소. 취소된 END 무시 | 복귀하면 사용자가 눌러야 다시 재생. 중복 콜백, 자동 진도 이동, 유령음 없음 |

2/4 도우 용량은 `capacity(M(2,4))=F(1,2)`, 3/4는 `F(3,4)`. 실제 fill로 `lengthIn(capacity(m),fill)`을 계산한다. 화면에 남은 **박 자리 수**는 단위 N(4)로 계산하고, 엔진의 `cells()`(8분음표 수)를 그대로 ‘박 수’로 표기하지 않는다. 새 이론 테이블이나 부동소수점 비교 판정은 도입하지 않는다. 같은 이벤트를 한 번만 처리하며, UI 차단과 별개로 모델도 초과 투입을 거부한다.

### 선택 확장과 수업 연결 (첫 30초의 통과 조건이 아님)

- **A · 2/4는 그대로, 음 시작만 바꾸기.** ‘두 조각’과 ‘긴 조각 하나’ 버튼으로 동일한 두 박 판에 `[N(4),N(4)]` ↔ `[N(2)]`를 얹는다. 한 번의 재생에서 전자는 두 번, 후자는 한 번만 음을 시작한다. 긴 조각 화면에서는 첫 박에서 시작한 강조 띠가 둘째 박까지 이어지며 박 번호·클릭은 두 번이다. 길이는 모두 4개의 8분음표 단위. 질문: ‘긴 소리가 이어지는 동안 박은 몇 번 지나갔나요?’
- **B · 길이는 그대로, 묶음만 바꾸기.** 정규 d3의 **발견 S3**에 이미 두 상태가 있다. 새 장면/씨앗을 만들지 않고 `DAYS → S3 → makeScene`의 상태를 읽는다. 그 자리에서 정규 S3를 만날 수도 있고, 후속판 선택 메뉴에서는 기록 없는 읽기 전용 미리보기로 돌려쓴다. 8분음표 6개의 속도·음높이·길이·총시간은 고정. 3/4의 큰 박 시작은 1·3·5번째(**2+2+2**, 4분음표 세 박), 6/8은 1·4번째(**3+3**, 점4분음표 두 박). 여섯 번 큰 박으로 세거나 6/8을 약분해 표시하지 않는다.
- **1차 릴리스에 후속 실험을 억지로 넣지 않는다.** [더 발견하기]는 실제 열린 콘텐츠가 있을 때만 노출한다. 처음에는 정규 교육과정 안내만 가능하며 [첫 주문으로]만으로 완결된다. 선택 확장 QA가 미달하면 숨겨도 핵심 목표에는 영향이 없다.

## 6. 소리, 화면 박 표시, 취소 설계

### 한 마디용 재생 악보

기존 `createAudioPlan`은 정규 박자표에서 한 마디 준비 + 두 마디 연주, 마지막에 0.2초 여유를 둔다. 자리 주문에는 별도의 자리음(A)·조각음(B) 비교가 있다. 그 기본값을 줄이면 기존 수업이 달라진다. **맛보기만** 전주 0, 반복 1, 끝은 정확히 한 마디인 별도 계획을 만든다. 재생 예약을 위한 짧은 기기 선행 시간은 음악의 전주가 아니다.

| 상태 | 8분음표 간격 e | 음 시작(초, 음악 시작=0) | 박 강조와 종료 |
|---|---:|---|---|
| 2/4, 4분음표 둘 | 기본 0.30 | 0.00, 0.60 | ①0.00 첫 박(강), ②0.60 다음 박(약); 1.20 종료 |
| 3/4, 4분음표 셋 | 0.30 | 0.00, 0.60, 1.20 | ①0.00 강, ②0.60·③1.20 약; 1.80 종료 |
| 2/4, 2분음표 하나 (선택) | 0.30 | 0.00만; 길이 1.20 | 박 클릭/번호는 0.00·0.60. 둘째 박에 새 음을 내지 않음 |
| S3, 8분음표 여섯 (선택) | 양쪽 모두 0.30 | 0.00, 0.30, 0.60, 0.90, 1.20, 1.50 | 3/4 큰 박 0.00·0.60·1.20, 6/8 큰 박 0.00·0.90. 둘 다 1.80 종료 |

수치는 기준판 기본값을 대입한 검증 예시이지 음표 길이표가 아니다. 시간은 `toSec`로 계산하며 ‘느리게’의 e=0.45라면 모든 시각이 1.5배가 된다. 첫 과제에서는 큰 박 클릭만 들리게 하고, 선택 S3에서는 여섯 음 시작은 모두 일정하게, 큰 박의 묶음만 차이나게 한다. 정규 설정 자체를 바꾸지는 않는다. 소리의 셈여림은 강박 위치를 시연하는 것이지 모든 연주의 절대 규칙이라는 뜻이 아니다.

**재생 소유권과 실패 처리**

1. 재생 요청 때 이전 요청을 취소하고 증가하는 요청 번호·소유자(`taster`, 정규, 메뉴 중 하나)·현재 상태를 캡처한다. ‘굽기’ 첫 사용자 탭에서만 오디오를 시도한다. 추가/빼기는 무음이며 첫 페이지 로딩으로 오디오를 열지 않는다.
2. 음소거·볼륨 0·Web Audio 미지원이면 즉시 시각 모드. 해제가 지연되거나 실패해도 비교를 막지 않는다. 시각 시간축은 즉시 시작하고 **이번 재생 시작 전에** 준비된 오디오만 붙인다. 뒤늦은 unlock으로 중간부터 소리를 붙이거나 다시 시작하지 않는다. 사용자가 [바로 비교]로 즉시 넘길 수도 있다.
3. 소리 사용 시 오디오 예약·프레임이 같은 t0, 같은 악보를 읽는다. 무음은 단조 증가 시계(`performance.now`)와 rAF로 동일한 박 좌표를 읽는다. 프레임이 빠져도 지난 박을 연속 재생하지 않는다. 프레임에는 조각 인덱스와 **박 인덱스를 분리**한다. 그래야 긴 음 하나가 두 번째 박에서 새로 터지지 않는다.
4. 탭 숨김, 지도·룰북·설정, 멈추기, 다시 재생, 화면 전환 모두 단일 취소 경로로 보낸다. 먼저 요청 번호 무효화 → RAF·타이머와 예약 노드 정지 → 화면의 강조 해제 → 해당 상태 복귀. END는 같은 요청·같은 화면·정상 완료일 때만 유효. 재생 전후 `game.completeBake()`, `stopBake()`를 호출하지 않는다. 인터럽트는 맛보기 안내만 갱신한다.
5. 재생 중 장치 오디오 시계가 멈추면 전경에서는 남은 구간을 무음 시각 시간축으로 한 번만 이어 주거나 [바로 비교]로 전환한다. 백그라운드는 이어 재생하지 않는다. 전역 `document.querySelectorAll('.slice,.sn')`/모든 `.on` 일괄 해제 대신 현재 판·보조줄 안에서만 강조한다. 뒷판·룰북의 그림이 함께 번쩍이지 않게 한다.

## 7. 터치·키보드·무음 수업 명세

- **좁은 화면:** 320×568 세로에서 제목, 두 자리, 올리기 버튼, 상태 줄이 첫 뷰포트 안에 들어오도록 장식부터 축소한다. 360×640/390×844, 태블릿, 데스크톱에서도 CTA 우선순위 동일. 확대 200% 및 가로 저높이에서는 스크롤을 허용하며 텍스트 생략이나 시작 불가를 피한다. 기존 `@media(max-height:551px){#rotate{display:flex!important}}`가 맛보기를 덮지 않도록 **맛보기에서만** 레이아웃 대체. 다른 화면에 무심코 회전 규칙을 전파하지 않는다.
- **손가락:** 주 버튼 최소 높이 48 CSS px, 나머지 터치 대상 44×44 CSS px 이상, 이웃 간격 8px 목표. 드래그·길게 누르기·원판 내 특정 좌표 맞히기 불필요. 한 번의 native click만 처리하고 pointerdown과 click을 중복 바인딩하지 않는다. 두 번 빠르게 눌러 두 조각을 놓는 것은 정상 입력이며 시간 기준 디바운스로 두 번째까지 삼키지 않는다.
- **키보드:** 기본 Tab→Enter/Space로 모든 조작. 첫 화면의 초점 문맥은 ‘두 박 피자’와 주 버튼에 있고, 추가 중에는 주 버튼 초점 유지. 꽉 차서 해당 버튼이 비활성화될 때만 굽기 또는 다음 유효 버튼으로 포커스 전달. Backspace=하나 빼기, Esc=재생 중단/열린 대화상자 닫기. 정규 숫자 1~6은 기존 매핑(4분음표는 5)을 유지. 맛보기에서 제공한다면 **5만** 같은 조각 추가, 다른 숫자는 무시. 0=전체화면 기존 동작. 입력폼·모달 안·키 자동 반복은 전역 단축키에서 제외. 본문 Enter와 포커스된 버튼의 기본 활성화를 중복 소비하지 않는다.
- **시각/청각:** 컬러만 보지 않아도 첫 박은 번호+‘첫 박’+선 굵기로 식별. SVG와 별도로 ‘4분의 2박자, 두 자리 중 한 자리 채움’ 같은 요약을 제공. 안내는 `role=status/aria-live=polite`로 배치 결과·완료만 한 번씩 읽고 박마다 스크린리더 발화를 큐에 쌓지 않는다. 무음·소리 권한 거부에서도 번호와 완료 요약은 동일.
- **움직임·초점:** reduced motion/시스템 설정 시 회전·튀기기 대신 번호 테두리만 교체. 포커스 표시를 숨기지 않는다. 멈추거나 대화상자를 닫아도 튜토리얼을 초기화하지 않는다. 실제 비활성 버튼과 `hidden`을 사용해 가려진 정규 쟁반·비교 버튼이 탭 순서에 남지 않게 한다.

**기준 명령 (후속 개발 시 실행):** Node 20 이상, 외부 패키지 추가 없이 `npm test` → `npm run build` → `cmp index.html dist/index.html` → `npm run dev`. 페이지 `#test`를 열고 루트 생성물을 오프라인에서도 열어 같은 결과를 확인한다. 기존 구현 기록의 **101개 Node 테스트와 96개 자가검사**는 당시 수치다. 현재 기준 커밋에는 룰북 테스트 파일도 있으므로 101을 현재의 합격 기준으로 고정하지 않는다. 기준판/변경판을 같은 환경에서 실제로 재실행해 ‘기존 통과분 손실 없음 + 신규 검사가 실제로 실행됨’을 저장한다. 두 번 빌드해 동일 생성물, 기존 단일 파일 예산 400KB 이내, 외부 런타임 요청 0을 확인한다. 이 문서는 위 명령을 수행한 결과 보고서가 아니다.

**되돌림:** `TASTER_ENABLED` 같은 내부 플래그 하나로 기본 진입과 다시 보기 링크를 함께 끄면 기존 title/map 루트로 돌아가게 설계한다. 정규 데이터·active·도장 마이그레이션은 하지 않는다. 이전 버전이 모르는 optional bool은 무시해도 정상이며 사용자의 저장소를 지우는 방식으로 되돌리지 않는다.

## 10. 수업 관찰: ‘이해했다’를 어떻게 확인할까

**U01 합격선: 처음 보는 학습자 5명 중 같은 4명 이상이 두 조건을 모두 충족한다.** ① 별도 조작 설명 없이 초회 화면이 조작 가능해진 시점부터 30초 이내 두 박 완성. ② 이후 비교를 끝내고 ‘4분음표 기준은 같고, 3/4에는 한 박 더 들어간다’는 뜻을 자기 말·가리키기·동등한 표현으로 설명. 두 조건을 따로 평균 내지 않는다. **비교 설명까지 30초 안에 말해야 한다는 뜻은 아니다.**

1. 새 세션을 5개 준비한다. 최소 2회는 좁은 휴대전화(1회 이상 무음), 나머지에도 다른 화면 크기·무음/유음 조건을 섞는다. 기기·설정과 첫 표시 시간을 적고 학생 이름·음성녹음은 수집하지 않는다.
2. 시작 말: **“이 피자를 한 마디만큼 채워 보세요.”** 어느 버튼인지, 몇 번인지 알려 주지 않는다. 시작은 첫 조작 가능 프레임, 종료는 두 번째 유효 입력이 반영되어 2/4가 찬 프레임. 화면 로딩 지연은 별도 열에 기록한다.
3. 관찰표: 익명 번호 | 화면·소리 | 첫 유효 탭까지 초 | 두 박 완료 초 | 3/4 추가 성공 | 도움/오조작 | 학생의 원문 요지 | 두 조건 모두 성공. 교사 개입은 그 학생의 독립 성공으로 세지 않는다.
4. 비교 직후 중립 질문: **“두 피자에서 같은 것과 달라진 것을 보여 줄래요?”** ‘하나 더’만 말하면 무엇 하나인지 중립적으로 확인. ‘조각이 커졌다’, ‘아래 숫자만 바뀌었다’, ‘모든 피자는 조각 하나가 무조건 한 박’은 미충족이다. 선택 A·B 지식은 U01에서 묻지 않는다.
5. 실패가 많으면 실패 위치를 기준으로 수정: 첫 탭 지연→헤더와 큰 버튼 대비, 두 번째 탭 누락→‘1박 남음’과 빈 자리, 3/4 설명 오류→두 판의 같은 조각 크기·‘더해진 ③’ 표시. 수정 후 같은 사용자에게 외운 답을 재시험하지 않고 새로운 초회 사용자로 다시 검증한다.
